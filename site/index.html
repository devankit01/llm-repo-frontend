What gets measured

Each eval asks a fixed number of questions sampled with a fixed seed, at temperature 0. Open an eval to see an example of what the model is asked and what counts as right.

Examples are written for this page to show the format. They are not rows from the datasets. Dataset licences are as listed on each dataset card; check the card before reusing the data.

Add a model

Any open model that runs in Ollama can be listed. You need Python 3.10 or newer, Ollama, and a GitHub account.

  1. Describe the model

    Fork the repo and add one file in data/models/. The file name is the model's id.

    // data/models/my-model-7b.json
{
  "id": "my-model-7b",
  "name": "My Model 7B",
  "developer": "Who released it",
  "params_b": 7,
  "license": "Apache-2.0",
  "license_type": "open-source",
  "ollama": "my-model:7b",
  "hf": "org/my-model-7b",
  "medical_tuned": false
}

  2. Run the evals

    Pull the model, then run the eval script. It downloads the datasets, asks the questions, and writes a results file.

    pip install -r evals/requirements.txt
ollama pull my-model:7b
python evals/run_eval.py --model my-model-7b \
  --hardware "M2 Pro, 16 GB" --submitted-by your-handle

  3. Check it

    Validate the data and look at the site locally before you send it.

    npm run check
npm start

  4. Open a pull request

    Commit the model file and data/results/my-model-7b.json. Keep the default sample count and seed so your scores are comparable with the others.

The full guide, including how to list a model without scores and how to propose a new eval, is in docs/ADDING_A_MODEL.md.

Not medical advice, and not clinical validation. A high score on these evals does not make a model safe to use in patient care. Scores come from small samples and are submitted by contributors.
